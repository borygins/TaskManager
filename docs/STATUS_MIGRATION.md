# Миграция статусов и отметок активности

Новая модель использует единый список статусов клиента и сохраняет в каждой активности снимок статуса и структурированные отметки. `create_all` не добавляет эти поля в существующую таблицу SQLite, поэтому старая база требует отдельной миграции.

## Порядок запуска

1. Остановите приложение и убедитесь, что завершены все процессы Uvicorn.
2. Если приложение просит сначала миграцию комментариев, выполните её по `COMMENTS_MIGRATION.md`.
3. Запустите:

   ```powershell
   python scripts/migrate_statuses.py --database task_manager.sqlite3
   ```

4. Убедитесь, что скрипт сообщил об успешной проверке целостности.
5. Запустите приложение обычным способом.

Перед изменением скрипт обязательно создаёт отдельную резервную копию в `backups`. Приложение не выполняет миграцию автоматически и отказывается запускаться на старой схеме.

## Преобразования

- `Согласие` преобразуется в `Переговоры`.
- `Договор подписан` и `Договор запущен` в истории соответствуют статусу `Подписан`.
- `Недозвон` становится отметкой `#недозвон`.
- `Перенос на дату` становится отметкой `#перезвонить`.
- Незнакомые статусы и результаты не преобразуются предположительно: скрипт остановится до создания изменений и перечислит значения.
- Незавершённые предпросмотры импорта помечаются устаревшими.

Повторный запуск уже выполненной миграции безопасен и не создаёт новый бэкап.
