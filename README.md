# TaskManager

Веб-задачник для менеджеров по продажам и руководителей. Система предназначена для ведения общих воронок продаж, назначения клиентов менеджерам, контроля статусов, звонков, комментариев, активности сотрудников и импорта/экспорта задач через Excel.

## Назначение системы

Приложение помогает работать с продажными кампаниями, где:

- воронки общие для всех пользователей;
- клиент уникален и хранится в одной карточке;
- один клиент закреплен только за одним менеджером;
- один и тот же клиент может участвовать сразу в нескольких воронках;
- руководитель видит всех клиентов и управляет распределением;
- менеджер видит только своих клиентов;
- изменения по клиенту фиксируются в журнале активности.

## Реализованные функции

### 1. Авторизация и безопасность

- вход по табельному номеру и паролю;
- роли пользователей: `manager` и `boss`;
- после сброса пароля или создания новой учетной записи стартовый пароль равен табельному номеру;
- при входе с временным паролем система принудительно отправляет пользователя на смену пароля;
- пока пароль не сменен, вход на главный экран запрещен;
- локальные пароли хранятся в виде хеша.

### 2. Работа с пользователями

Для роли `boss` доступен отдельный раздел управления пользователями.

Руководитель может:

- создать нового пользователя;
- указать табельный номер;
- указать ФИО;
- назначить роль `Менеджер` или `Руководитель`;
- изменить роль существующего пользователя;
- назначить роль бессрочно;
- назначить роль временно до указанной даты;
- задать возврат роли после окончания временного периода;
- вручную сбросить пароль любого пользователя до табельного номера.

### 3. Работа с воронками продаж

- воронки общие для всех пользователей;
- по умолчанию созданы две воронки: `Доля рынка` и `Спарк`;
- один клиент может находиться в нескольких воронках одновременно;
- в карточке и списках видно, если клиент участвует в нескольких воронках.

### 4. Работа с клиентами

У клиента поддерживаются поля:

- ФИО;
- организация;
- ИНН;
- телефон;
- дата звонка;
- следующая дата звонка;
- дата последней активности менеджера;
- статус;
- оборот в месяц;
- MCC;
- банк-конкурент;
- адрес регистрации;
- история комментариев к активности.

### 5. Статусы клиента

Поддерживаются статусы:

- `Поиск контакта`
- `Отказ`
- `Переговоры`
- `Согласие`
- `Мискодинг`
- `Подписан`

### 6. Представление воронки для менеджера

Воронка отображается в виде компактного списка строк, а не больших карточек.

В списке видно:

- ИНН;
- организацию;
- текущий статус;
- последний комментарий;
- дату последней активности;
- кнопку открытия полной карточки клиента в новой вкладке.

### 7. Полная карточка клиента

Полная карточка открывается отдельно и позволяет:

- изменять основные поля клиента;
- менять статус;
- назначать даты звонка;
- оставлять комментарии к активности;
- просматривать историю комментариев;
- руководителю менять ответственного менеджера;
- сохранять изменения одной кнопкой.

### 8. Фильтры и поиск

В воронке продаж доступны:

- единый поиск по ИНН, ФИО и организации;
- фильтр по статусу;
- фильтр по следующей дате звонка.

Это позволяет, например, быстро собрать всех клиентов, которым нужно звонить в определенный день.

### 9. Распределение клиентов руководителем

На отдельной странице `Распределение клиентов` руководитель может:

- искать клиентов по ИНН, ФИО и организации;
- фильтровать по статусу;
- фильтровать по текущему менеджеру;
- назначать конкретного клиента на другого менеджера;
- массово назначать всех клиентов из текущей отфильтрованной выборки на выбранного менеджера.

### 10. Журнал активности

Система фиксирует активность по клиенту:

- изменение статуса;
- изменение дат звонка;
- изменение ответственного менеджера;
- изменение важных полей клиента;
- добавление комментариев к активности.

Особенность журнала:

- за один день по одному клиенту не создается множество отдельных записей;
- все изменения за день дописываются в одну общую запись;
- внутри записи сохраняются время и текст каждого изменения.

### 11. Комментарии

- комментарии ведутся в формате `Комментарии к активности`;
- комментарий попадает в историю клиента;
- комментарий также отражается в журнале активности.

### 12. Импорт и экспорт Excel

Поддерживается массовая загрузка и выгрузка задач.

#### Импорт

Руководитель может:

- скачать шаблон импорта;
- заполнить Excel по шаблону;
- загрузить файл в систему.

#### Экспорт

Экспорт включает:

- ФИО клиента;
- организацию;
- ИНН;
- телефон;
- комментарий менеджера;
- дату звонка;
- следующую дату звонка;
- дату последней активности менеджера;
- статус;
- оборот в месяц;
- MCC;
- банк-конкурент;
- адрес регистрации;
- список воронок;
- табельный номер менеджера;
- ФИО менеджера.

Менеджер выгружает только своих клиентов. Руководитель выгружает всех.

### 13. База данных и резервное копирование

- используется SQLite;
- включен WAL-режим;
- база создается автоматически при первом запуске;
- ежедневный бэкап создается автоматически;
- руководитель может вручную создать бэкап из интерфейса.

## Интерфейс

- темная тема;
- современный интерфейс на HTML + CSS;
- отдельные страницы для входа, воронок, карточки клиента, активности, распределения клиентов и управления пользователями.

## Стек

- Python 3.13
- FastAPI
- SQLAlchemy Async ORM
- SQLite в WAL-режиме
- Jinja2 Templates
- HTML + CSS
- openpyxl
- APScheduler
- aiosqlite

## Структура проекта

- `app/main.py` - маршруты FastAPI и основная точка входа;
- `app/models/` - ORM-модели;
- `app/db/` - инициализация базы данных;
- `app/services/` - бизнес-логика, импорт/экспорт, бэкапы, сидирование;
- `app/templates/` - HTML-шаблоны;
- `app/static/` - стили и фронтенд-ресурсы;
- `docs/` - дополнительная документация;
- `backups/` - резервные копии базы.

## Быстрый старт

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

После первого запуска приложение создаст:

- базу `task_manager.sqlite3`;
- тестовую учетку начальника `01333777 / SEEDED_BOSS_PASSWORD`;
- тестовую учетку менеджера `01666222 / SEEDED_MANAGER_PASSWORD`;
- две стартовые воронки: `Доля рынка` и `Спарк`.

## Доступ к системе

- URL: `http://<ваш-ip>:8000`
- порт: `8000`
- веб-сервер рассчитан на локальный запуск на компьютере пользователя

## Ограничения текущей версии

- пока нет Alembic-миграций;
- пока нет полноценной истории админских действий по смене ролей и сбросу пароля;
- HTTPS не поднимается самим FastAPI, лучше использовать внешний reverse proxy или локальный сертификат;
- пока используется SQLite, но структура проекта готовится к переходу на PostgreSQL.
